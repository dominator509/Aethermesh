# OPERATIONS

## Local Operations
| Action | Command |
|---|---|
| Run layer demo | `uv run python -m aethermesh.demos.layerN` |
| Init audit DB | `uv run python -m aethermesh.tools.init_audit_db --path ./audit.db` |
| Bootstrap directory | `uv run python -m aethermesh.tools.bootstrap_directory --out ./directory.json` |
| Inspect audit log | `uv run python -m aethermesh.tools.audit_db ls --path ./audit.db` |

## Staging Operations
Use `ops/staging/docker-compose.yml` (generated by EP-009).

## Production Operations
Per-operator. Per-role runbooks below define the protocol boundary.

### Mix Node Runbook
1. Provision VM with `aethermesh-mix-node` image.
2. Generate `node_sk` + `node_pq_sk`:
   ```sh
   docker run --rm ghcr.io/<org>/aethermesh-mix-node:X.Y.Z \
     python -m aethermesh.tools.gen_node_keys \
     --out-classic /run/secrets/node_sk \
     --out-pq /run/secrets/node_pq_sk
   ```
3. Register node id with directory authority (out-of-band).
4. Start container (see DEPLOYMENT.md).
5. Confirm health: `curl http://localhost:9100/healthz` → `ok`.
6. Confirm metrics: `aep_l1_packets_total` rising.

### Gateway Runbook
Same with `AEP_NODE_ROLE=gateway-entry|exit`. Additionally:
- Public UDP port reachable.
- Local PQ KEM keypair rotated per epoch.

### DHT Node Runbook
- Bootstrap routing table from ≥ 3 peers.
- `aep_l2_dht_records_stored_total` non-zero within 10 min.
- `AEP_REVOCATION_FETCH_INTERVAL_S` ≤ 300 s.

### Keyring Service Runbook
- Starts only inside platform TEE (SEP / StrongBox / TPM2).
- Refuses to serve if `AEP_PQ_BACKEND=placeholder`.
- Audit log user-owned; never read by operator tooling.

## Health Checks
| Endpoint | Port | Expected |
|---|---|---|
| `/healthz` | 9100 | `ok` (200) when up ≥ 5 s |
| `/readyz` | 9100 | `ok` when directory loaded + keys present |
| `/metrics` | 9100 | Prometheus exposition |

CLI: `aethermesh node health`.

## Common Failure Modes
| Symptom | Diagnosis | Action |
|---|---|---|
| Replay cache hit rate > 1% | DoS replays or clock skew | Inspect upstream; ntpd resync |
| Mix key rotation lag (> 5 min) | Directory fetch failed | `aethermesh node refresh-directory` |
| DHT eclipse suspected | All find_node responses converge | `AEP_DHT_BOOTSTRAP_OVERRIDE` to known-good; report to dir authority |
| Audit DB locked | Two writers | Stop one; systemd `BindsTo` |
| Cover traffic stalled | `aep_l1_packets_total` flat | Check gateway connection + rate config |
| Handshake p95 > 1 s | TEE latency or RTT | Inspect `aep_l3_attestation_verifications_total` by backend |

## Troubleshooting
`aethermesh node diagnose` writes `diagnose-report.json`. Attach to any incident ticket.

## Audit DB Backup / Restore
```sh
sqlite3 /var/lib/aethermesh/audit.db "VACUUM INTO '/backup/audit-$(date -I).db'"
cp /backup/audit-2026-01-15.db /var/lib/aethermesh/audit.db && docker restart aethermesh-mix-1
```

## Scheduled Jobs
| Job | Cadence | Action |
|---|---|---|
| Mix key rotation | 3600 s | New X25519 (+ ML-KEM for gateways) |
| Revocation manifest poll | `AEP_REVOCATION_FETCH_INTERVAL_S` | Pull, verify, cache |
| Replay cache eviction | 60 s | Drop entries > 2 × max_path_delay |
| Loop-cover health | 30 s | Emit self-loop; alert if RTT not seen in 3 × interval |

## Incident Triage
1. Identify firing alert's layer.
2. Pull `diagnose-report.json`.
3. Open relevant runbook.
4. Unresolved in 15 min → page on-call.

## Escalation Rules
| Severity | Definition | Page |
|---|---|---|
| SEV-1 | Protocol invariant broken | Immediate; release lead + security |
| SEV-2 | Layer down on > 30% of nodes | Within 15 min |
| SEV-3 | Perf regression > 20% | Within 1 h |
| SEV-4 | Doc gap or single-operator issue | Next business day |

## Operational Safety Rules
- Never edit `audit.db` by hand.
- Never publish `RevocationManifest` without explicit user permission.
- Never disable cover traffic in production.
- Never run a mix node and a keyring in the same container.
